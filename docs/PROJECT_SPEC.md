## 1. 目的と適用範囲

本書は、October2026の日本語学習ページで共通に用いる学習設計、テキストデータ、音声機能、回答判定、学習支援機能の仕様を定める。

- 対象は日本語Practiceを中心とする日本語学習ページ、Composition、Pronunciationのうち、各機能が適用されるものとする。
- 共通機能は、現時点ですべての対象ページに実装されていることを条件としない。ページごとの段階的導入を認める。
- Deutsche Übung 1.1のドリル固有仕様は対象外とし、`GERMAN_DRILL_SPEC.md`を正本とする。
- ページ固有の設問構成・許容回答・例外は各ページ仕様書を正本とする。本書の共通原則でページ固有の条件を上書きしない。

## 2. 仕様と実装状況の区別

仕様書・実装報告では、次の3区分を混同しない。

1. **確定仕様**：今後守るべき動作・教材上のルール。
2. **現行実装**：確認時点のコードが実際に行っている動作。
3. **実装未反映・不具合**：確定仕様と現行実装の差。コードが未対応であることを理由に確定仕様を縮小・変更しない。

実装状況を記述する場合は、確認したコード・テスト・確認日を区別する。コードを読んだだけの確認を、テスト実行済み・実機確認済みと表現しない。

## 3. 共通学習設計

### 3.1 教師指定教材の保持

- 教師が提供・確定したキューは、語句のまとまり、分割位置、順序、助詞の有無を含めて教材の確定データとして扱う。
- 教師の承認なく、AI・コード生成・表示整形・内部データ化の都合で、キューを分割・結合・補完・削除・並べ替えしない。
- 元キューとモデル文・モデル音声の文法構造に不一致が疑われる場合、元キューを黙って修正せず差異を報告する。元データを確認できないときは「未確認」とする。
- キューとモデルの構造整合を理由に、自然な別解や既存の回答許容範囲を狭めない。正答範囲はページ固有の判定仕様に従う。

### 3.2 Genki進行と表示

- Practice Nのキューは、原則としてGenki Lesson Nまでの漢字学習進行に合わせ、未習漢字をかなで表示する。
- Exampleのモデル文は、With Kanjiでは自然で一般的な漢字表記を使用できる。Hiragana Onlyでは表示用の文をかなにする。
- 表示上の漢字変換は、TTS用テキスト・STT原文・回答判定用テキストへ流用しない。
- 文脈上「も」が適切な場合は、モデル文・モデル音声に「も」を用いる。Speech Styleを理由に意味を担う「も」を機械的に省略しない。

### 3.3 Sneak Peek

- 当該Lessonの教科書で扱わない内容を教師が補足・先取りとして提供する場合、Drill等のタイトルには原則 `[Sneak Peek]` を用いる。
- `[Advanced]`（難易度）と混同しない。
- `Sneak Peek L{N}`は、その内容が実際に当該後続Lessonで扱われることを確認できた場合に限る。単語索引への掲載だけから導入Lessonを推測しない。
- 既存全ページへの一括追加は行わず、新規制作・更新時に必要に応じて適用する。

### 3.4 Beyond Words / Kanji

- ボタン名は **Beyond L{N} Words** とし、Nはページが対応するGenki Lesson番号とする。
- **Words**には、対象Lessonより後で導入される語彙・表現、またはGenki外の語彙・表現を掲載する。対象Lessonまでに学習済みの語を、未習漢字を含むという理由だけでWordsへ追加しない。
- **Kanji**には、当該ページの表示用語句・モデル文等に登場し、対象Lesson時点で未習の漢字を、漢字入り語句・読み・漢字配当課とともに掲載する。
- 語彙の初出課と漢字の配当課を区別する。掲載根拠を確認し、推測で課配当を決めない。
- 同じ語がWordsとKanjiの両方に掲載されること自体は禁止しないが、それぞれの掲載条件を独立に満たす必要がある。
- ページ表示内容を対象とし、TTS内部文やSTT結果から項目を追加しない。リスト掲載のためにExample本文をかなへ変更しない。

## 4. テキストデータと音声データ

### 4.1 5種類のテキストデータを分離する

次のデータは役割が異なるため、ひとつの文字列を使い回して相互に上書きしない。

| 種類 | 役割 | 保持原則 |
| --- | --- | --- |
| 1. モデル表示テキスト | 画面に表示する模範文 | Script Mode等の表示変換は表示層に限定する |
| 2. TTSテキスト | 読み上げに渡す文 | 発音・ポーズを優先し、表示用の加工から独立させる |
| 3. raw STT | 音声認識エンジンが返した原文 | 認識結果をそのまま保持し、自動修正しない |
| 4. 表示用STT | 学習者画面に表示する認識文 | 表示専用の変換のみを行い、raw STTを変更しない |
| 5. 判定用テキスト | 正誤判定の比較に使う文字列 | 比較用正規化を行ってもraw STT・表示用STTを上書きしない |

- 表示変換、音声生成用の句読点・ポーズ挿入、STT表示変換、回答正規化を別々の処理として扱う。
- STT表示ルールの詳細と例外は`STT_DISPLAY_RULES.md`を正本とする。
- 表示上の漢字・かな変換や句読点の強調処理を、TTS・STT原文・判定用データへ流用しない。

### 4.2 TTSの句読点・ポーズ

- TTS用内部文は発音の自然さと意味単位のポーズを優先する。
- 読点「、」は必要な文節境界・ポーズを示すために使い、句点「。」は文末として扱う。単純な文字数やキューの区切りだけで機械的に挿入しない。
- 既存の節・名詞化節など、文法的にひとまとまりの構造を不必要に分断しない。
- TTS用の句読点を画面表示モデル・STT表示・判定用テキストへ転用しない。

### 4.3 日本語音声の選択優先順位

- 利用者がGlobal Settings等で選択・保存した音声が現在の環境で利用可能な場合、その選択を最優先する。
- 保存音声が利用できない場合の候補優先順位は次のとおりとする。名称の完全一致だけでなく、OS・ブラウザが返す音声名の表記差を考慮して照合する。
  1. Chrome Japanese 3（名称の候補一致。単純な「3番目の音声」という意味ではない）
  2. ChromeOS Japanese voice
  3. Google Japanese voice
  4. Microsoft Nanami
  5. Microsoft Keita
  6. Microsoft Haruka
  7. その他の日本語音声
- 利用できない音声を選択済みと表示しない。実際に選択・再生した音声とフォールバックを区別する。

### 4.4 通常ドリルのTTS速度

- 新規作成・改修する通常の日本語Drillでは、TTS速度の標準値を **0.9** とする。
- ページ番号やLesson番号に比例させて、速度を機械的に引き上げない。
- 既存ページで0.75または0.8等を使用している場合、本仕様書再編だけを理由に一括変更しない。既存値は個別に決定するまで維持する。
- 0.9を超える速度は、具体的な教育上の必要性が確認できた場合に個別検討する。
- CompositionとPronunciationは通常Drillと音声上の目的が異なるため、同じ速度を自動適用せず、それぞれの目的に基づき判断する。
- Global Settingsから利用者がTTS速度を選択する機能は将来候補（FWC W10・保留）であり、本仕様の確定済み実装要件ではない。

## 5. Global Settingsと録音機能

### 5.1 共通設定の役割

ページが採用する場合、Script Mode、Speech Style、Vocab表示、Autostop／Manual、Autoplay／Manual、音声選択等は共通の操作原則に従う。共通機能の存在は、すべてのページへ同じ設定項目を一律追加する義務を意味しない。

- **Script Mode**：表示用の漢字・かな表記を切り替える。TTS・STT原文・判定データを変更しない。
- **Speech Style**：ページが提供するFormal／Informal／Casual等の文体をモデル・回答判定に反映する。ページ仕様にない文体や回答形式を自動追加しない。
- **Vocab**：ページに実装された語彙補助表示の表示モードを切り替える。OFF／Hover／Displayの表示上の挙動は共通UI仕様に従う。
- **Autostop／Manual**：自動停止と手動停止の動作を切り替える。
- **Autoplay／Manual**：録音後の音声再生動作を切り替える。
- 録音・再生中は、録音状態を壊す設定変更や重複操作を抑止する。必要な状態・録音結果・音声URL・回答選択を、再描画や設定変更で不意に消去しない。

### 5.2 録音停止条件（F4・確定仕様）

対象：日本語Practice、Composition、Pronunciation。Deutsche Übung 1.1は対象外とし、`GERMAN_DRILL_SPEC.md`に従う。

対象ページでは、Autostop／Manualを問わず、録音停止時間の統一値を次のようにする。

1. **発話開始前：5秒**。録音開始から5秒間、発話が検知されなければ自動停止する。
2. **発話後：2.0秒**。Autostop ONの場合、発話後に連続2.0秒の無音が検知されたら自動停止する。Manualでは発話後の無音による自動停止を行わない。
3. **絶対上限：20秒**。録音開始から20秒で、発話の有無・Autostop／Manualを問わず必ず停止する。

#### 発話後2.0秒の無音検知に関する技術補足

- 2.0秒は、SpeechRecognitionの認識終了イベントが発生してからの待ち時間ではなく、マイク入力における**連続した無音時間**として定義する。
- 無音の判定はマイク入力の音量レベルを監視して行う。Web Audio APIの`AudioContext`／`AnalyserNode`等によるレベル監視を基本的な実装候補とする。
- 発話後、音量レベルが無音判定範囲を連続2.0秒下回った場合に停止する。音量が発話判定範囲へ戻った場合は、無音継続時間をリセットする。
- `SpeechRecognition.onend`等の認識イベントだけを、連続2.0秒の無音検知の代替として扱わない。
- 音量閾値、平滑化、サンプリング間隔等の未確定数値は、この仕様書で独断して追加しない。技術方式の共通化は実装状況に応じて判断できるが、利用者から見た停止条件と時間は対象ページで統一する。

#### 現行実装との差の扱い

- 5秒の発話開始前タイムアウトは確定仕様である。現行コードに15秒が残っている場合は実装未反映として扱い、15秒を確定仕様へ戻す根拠にしない。
- 発話後2.0秒の停止も確定仕様である。ページごとに認識イベント依存・音量レベル監視等の方式が異なっている場合、その差を記録する。動作が2.0秒の連続無音停止を満たさなければ実装未反映／不具合とする。
- 20秒の絶対上限はすべての対象ページで維持する。
- 統一値に一致しないページ・機能が判明した場合は、Fリスト対象として記録し、実装方法・共通化の要否を別途検討する。

### 5.3 録音・状態保持

- 録音開始中・録音中・停止処理中の状態を区別し、重複録音・競合する再生・設定変更による状態破壊を防ぐ。
- 録音完了後のraw STT、表示用STT、判定結果、録音音声URL、回答選択等は、当該ページで定めた保持期間中、再描画や設定切替によって不意に消去しない。
- 中断・破棄・ページ離脱時の後始末は、録音ストリーム・タイマー・音声URL等のリソースを残さない。
- 各ページの録音UI・データ構造・状態遷移の詳細は、ページ仕様書と実装に対応する共通モジュール仕様を参照する。

### 5.4 「きく」「とる」の共通実行条件

- **基本原則**：学習操作の前提となる選択または入力が不十分な場合、「きく」ボタンを無効化（disabled）する。実行条件が未充足の場合、「とる」ボタンを無効化（disabled）する。
- **モデル音声と録音の関係**：モデル音声の再生完了を録音の前提条件にしない。前提条件が揃っていれば、モデル音を聞かずに直接録音へ進める。
- **理由説明の提示**：条件不足により無効化されている場合は、外側の説明枠（ツールチップ等）で利用者に理由を表示する。
- **排他ロックとの分離**：マイク許可待ちや録音中などの排他ロックは別途適用し、ロック中に「選択／入力不足」という不正確な理由説明を出さない。
- **適用範囲**：適用対象は、本仕様書および各ページ仕様に定められた既存の共通仕様対象（1.1 D2のX/Y選択、1.1 D3のX/Y入力、1.2 D2返答の専攻選択、1.2 D1および7.1〜7.3 D2返答の🙆/🙅選択等）に従う。今回の整理で対象ページを新たに追加・拡張しない。
- **外観・配置・ツールチップ仕様**：ボタンの配置、外観、ツールチップの具体的な表示・レイアウト仕様は `UI_LAYOUT_SPEC.md` を正本とする。

## 6. 共通回答判定

### 6.1 raw STTと判定用正規化

- raw STTは認識原文として保持する。
- 正規化は比較のためだけに使い、raw STTや表示用STTへ書き戻さない。
- 数字、助詞、文体、音声認識揺れ等の許容は、共通ルールで無条件に拡張せず、ページ・設問ごとに登録された範囲で適用する。
- 数字の漢数字・算用数字・かな読みの正規化は、対象単位・設問で許可された場合に限る。異なる数値を同一視しない。

### 6.2 文末助詞「よ／ね／よね」

- 日本語の録音回答では、ページ・設問の回答条件に反しない範囲で、文末の「よ」「ね」「よね」を内容判定上の許容差として扱える。
- これは文末助詞をraw STTや画面表示から削除する規則ではない。認識原文と表示は保持する。
- ページ固有の敬体・常体・Formal等の条件、必須助詞、疑問形式等を破ってまで許容しない。

### 6.3 Formalの疑問文「か」

Formalの質問として判定する対象は、ページ仕様に別の明示がない限り、疑問の終助詞「か」を必要とする。SpeechRecognition由来の句読点差だけを理由に判定を変えない。

### 6.4 ページ固有の回答範囲

- 短答／全文回答、主語省略、助詞省略、同義表現、語順、数値表記等はページ仕様で定める。
- 一つのページ・設問で認めた例外を、他ページや全設問へ機械的に一般化しない。

## 7. 共通学習支援機能

### 7.1 English Cues

- English Cuesは、対応するDrillで日本語のキューに代えて英語の手掛かりを表示する共通再利用機能である。
- 機能を採用するページ・Drillで、既存のモデル文、モデル音声、回答判定の正解、教材構成を変更しない。
- 英語キューは対応する日本語キューの意味を示し、未登録の情報や別解を勝手に追加しない。
- 表示切替後も、録音結果・音声URL・回答選択等の状態を保持する。
- English Cuesは全ページ必須ではない。教材上必要なページへ段階的に導入する。

### 7.2 Copy my sentences

- **新規作成する録音付きDrillには、Drill単位の`Copy my sentences`機能を標準搭載する。** 録音対象のないDrill・Exampleへ機械的に追加しない。
- 既存ページへ一括追加する指示ではない。各ページへの展開は、録音対象と記録データをRead-onlyで確認してから行う。
- Pronunciation 1・2およびCompositionは標準対象外とする。対象範囲を広げる場合は別途判断する。
- コピー対象は、そのDrillで認識された学習者本人のraw STTのみとする。モデル解答、設問、TTS内容、未録音行、別Drillの記録を混ぜない。コピー時に学習者の誤りを自動修正しない。
- 見出しは `Practice {page} — Drill {number}: {drill name} — {learning focus} — YYYY-MM-DD` を標準とする。ページ固有の明示定義からDrill名・学習テーマを生成し、日付はコピー操作時の利用者ローカル日付を一度だけ付与する。
- 既存の正誤マーカーやQ/A等の区分がある場合は保持する。
- 有効な発話記録がないとき、または録音開始中・録音中はコピー操作を無効にする。クリップボード操作の失敗を成功として表示しない。
- ボタンのアイコン、文字、補助説明、配置、余白等の視覚仕様は`UI_LAYOUT_SPEC.md`を正本とする。
