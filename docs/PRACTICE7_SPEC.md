## 2. Practice 7.1 — Habits

### 2.1 Habitを表す文

- 対象文では、習慣を示す「いつも」と対象の動詞の両方を必要とする。
- 「いつも」の位置は、登録された文として自然な範囲で前後を許容する。
- 「いつも」がない文、または動詞がない断片は正解にしない。

| 回答例 | 判定 |
| --- | --- |
| 映画をいつも見ます | 正解 |
| いつも映画を見ます | 正解 |
| 映画を見ます | 不正解（いつもがない） |
| いつも映画を | 不正解（動詞がない） |

- 「英語を／英語で」等の助詞例外は、該当する登録設問に限る。特定行の例外を全設問へ一般化しない。

### 2.2 Q/A回答

- 回答は各設問に登録された応答語・人物・時間・対象・肯定／否定条件に従う。
- `今`、`私`、対象語等の要素を省略できるかは行ごとの登録条件による。
- 対象語を回答に含める形式では、設問に合った対象であることを確認する。別の対象を同一視しない。
- 同じ語の繰り返しを許容するかは既存の設問別判定に従う。
- Casualの目的語助詞「を」の省略は、許可された行だけで認める。

## 3. Practice 7.2 — Current state / present perfect

### 3.1 主語・助詞

- 登録された設問では、主語の「は／が」または文脈上の主語省略を許容する。
- 主語位置の「を」は、当該設問の登録例外がない限り許容しない。
- 主語助詞の選択を、別の設問や目的語へ一般化しない。

### 3.2 電話番号の目的語

- 電話番号を目的語として答える登録設問では、「を／は」または登録された省略を許容する。
- 同じ箇所の「が」は許容しない。
- これは電話番号の該当設問だけの例外であり、他の目的語の助詞に一般化しない。

### 3.3 知るの否定

- `知る`の否定は、登録された文体に応じて`知りません`／`知らない`を使う。
- `知っていません`、`知っていない`、`知ってない`は、該当する否定回答として許容しない。
- この制約を他の動詞の否定形へ機械的に適用しない。

### 3.4 数量・時間の表記揺れ

数値の正規化は、次の登録対象に限って認める。数字が異なる回答を同一視しない。

| 基準表現 | 登録された表記・読みの例 |
| --- | --- |
| 十時 | 10時／１０時／じゅうじ |
| 五十個 | 50個／５０個／ごじゅっこ／ごじっこ／ごじゅうこ |
| 三年前 | 3年前／３年前／さんねんまえ |

- 単位（時・個・年前）を含む登録対象ごとに比較し、任意の数値・単位へ正規化を広げない。
- 表記の正規化は判定専用とし、raw STTと表示用STTを変更しない。

## 4. Practice 7.3 — Past ongoing

### 4.1 時間表現の省略と一致

- Drill 2のQ/Aでは、会話上明らかな場合に時間表現を省略できる。
- 時間を明示する場合は、設問の指定時間と一致させる。
- 設問で許容される範囲では、同じ時間表現の繰り返しを認める。

### 4.2 登録された時間表現の同義語

次の同義語は、該当する時間表現の登録回答に限って許容する。

| 基準表現 | 許容表現 | 条件 |
| --- | --- | --- |
| 今日の午前中 | 今朝／けさ／今日の朝 | 対応する設問の時間表現として使う場合 |
| 昨日の夜 | 昨夜／昨晩／さくや／さくばん／昨日の晩 | 対応する設問の時間表現として使う場合 |
| 昨日の午前中 | 昨日の朝 | **具体的な時刻を伴わず、時間帯だけを表す場合** |
| さっき | 先ほど | 対応する設問の時間表現として使う場合 |
| 昨日の昼 | 昨日のお昼 | 対応する設問の時間表現として使う場合 |

「昨日の朝」は「昨日の午前中」の許容表現として追加する。ただし、`昨日の朝8時`等の具体的な時刻を伴う場合まで無条件に同義として扱わない。具体的な時刻がある場合は、時刻そのものの一致を別途確認する。

### 4.3 友達に会う／友達と会う

- 該当する登録設問では、「友達に会う」と「友達と会う」を同じ意味の回答として許容する。
- この許容は当該設問・対象表現に限定し、他の動詞の「に／と」へ一般化しない。

### 4.4 数字・時間の正規化

- 数字・時間の正規化は、登録された数値・単位・表現に限定する。
- 時刻・数量・経過年数等の値が異なる回答は不正解とする。
- 正規化は判定専用とし、raw STT・表示用STTを上書きしない。

## 5. 共通制約

- 設問別の許容回答を、同じPractice内の別設問や他Practiceへ機械的に適用しない。
- キューの語句分割・順序・助詞を、判定実装の都合で変更しない。
- 音声・テキストの保持、録音停止、TTS、STTの共通仕様は`PROJECT_SPEC.md`に従う。
- Copy my sentencesは、新規作成する録音付きDrillの共通標準に従い、既存ページへの追加は別途確認して行う。

## 6. 現行実装の確認と差の記録

本書では、次の3項目を分けて記録する。

1. **確定仕様**：今後守るべき回答許容・判定条件。本書の§2～§4を正本とする。
2. **現行実装**：コードを確認した時点で、対象ページが実際に行っている処理。コード未確認の場合は「未確認」と記載する。
3. **実装未反映・不具合**：確定仕様と現行実装の差。コード未確認の場合は「未判定」とし、未確認であることだけを理由に不具合・未反映と断定しない。

同義語・数値表記は、ページデータ、正規化処理、回答判定の登録範囲を照合する。コードを読んだ確認とテスト実行・実機確認を混同しない。コード確認後は、各行の現行実装と差の欄を更新する。確定仕様を現行コードに合わせて縮小しない。
