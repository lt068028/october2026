## 1. ページの学習目標・共通表記

- ページ名・HTML title・Index表示は **Practice 2.1: これ・それ・あれ・どれ — Demonstrative Pronouns** とする。Practice 2.2はDemonstrative Adjectivesとして対比する。
- こ／そ／あは、現在の話者と聞き手からの距離を示す。話者が交代した場合は、同じ物の位置関係に応じて指示表現を切り替える。
- どは未知の対象について尋ねる表現として扱い、こ／そ／あの第4の場所を表すものではない。
- 既定のScript ModeはHiragana Onlyとする。With漢字ではGenki語彙欄の参考漢字を使用し、かばんは「カバン」と表記する。「鞄」は画面表示に使わない。画像内に描かれた文字はScript Modeによる変換対象外とする。
- 文脈上「も」が適切な場合はモデルに「も」を使用する。正しい「は」版や自然な短答は、該当設問で登録された範囲に限って許容する。
- 「何ですか」のモデル／TTSは「なんですか」を基準とする。「なん／なに」の差は該当する回答照合の許容範囲で扱い、読み表示や判定用の変換でraw STTを書き換えない。詳細なデータ分離と正規化は `PROJECT_SPEC.md` に従う。

## 2. Example 1 — こ・そ・あ

### 2.1 図と位置関係

- 図の人物はX／Yの2人とし、内部の話者ID A／Bと混同しない。人物ラベルや発話中の強調の外観は `UI_LAYOUT_SPEC.md` §7.3に従う。
- X側の品物は本、Y側の品物はかばん、両者から遠い位置の品物は時計とする。
- こ／そ／あの説明は、現在の話者を基準として「話者の近く／聞き手の近く／両者から遠い位置」を示す。話者が交代しても、人物・品物の物理的位置は変えない。
- 各品物にX／Yそれぞれのモデル音声操作を用意し、各操作は対応する話者の1文だけを再生する。キーボードフォーカスによる図の対象切替は音声再生を開始しない。
- 2.1では「Who is speaking?／X is speaking／Y is speaking」の案内表示を設けない。発話者の識別は、人物ラベルと共通の話者強調で示す。

### 2.2 モデル文

| 品物 | X（内部A）のモデル | Y（内部B）のモデル |
| --- | --- | --- |
| 本 | これは、ほんです。 | それは、ほんです。 |
| かばん | それは、かばんです。 | これは、かばんです。 |
| 時計 | あれは、とけいです。 | あれは、とけいです。 |

- Script Modeに応じて、本／ほん、カバン／かばん、時計／とけいを切り替える。
- Formalは「です」、Informalは「だ」、Casualは「だよ」とし、モデルの主題「は」を残す。
- 画像内の品物・Example本文の語彙ヒントは、承認済みのPractice 2固有の表示として維持する。Hover／Display／OFFの共通動作は `UI_LAYOUT_SPEC.md` に従う。

## 3. Drill 1 — 指示表現と訂正返答

### 3.1 Set 1：単独文

- X（内部A）は「これ／それ／あれ」を用いて、X側→Y側→遠方の順に3文を述べる。続けてY（内部B）も、Y側→X側→遠方の順に3文を述べる。
- 1文ごとに個別の音声・録音・停止・認識結果・判定を設ける。3文をまとめて録音しない。
- Set 1の品物は、X側がペン、Y側が新聞、遠方が帽子とする。

### 3.2 Set 2：質問と訂正返答

- 現在の品物と異なる品名をXが質問し、Yが否定して正しい品名へ訂正する3組、合計6行とする。各質問・返答は個別に再生・録音・判定する。
- 品物はX側がノート、Y側が鉛筆、遠方がTシャツとする。

| Xのキュー | Xのモデル（Formal） | Yのモデル（Formal） |
| --- | --- | --- |
| これ／えんぴつ | これは、えんぴつですか？ | いいえ、ノートです。 |
| それ／Tシャツ | それは、Tシャツですか？ | いいえ、えんぴつです。 |
| あれ／ノート | あれは、ノートですか？ | いいえ、Tシャツです。 |

- Yの返答キューは「いいえ／正しい品名」とする。停止ボタン横の固定補助文は「いいえ…」とし、Casualでは「ううん…」へ切り替える。返答する指示語はキューに追加しない。
- Set 2の品物の色は識別のために使用し、色名を発話・語彙ヒント・正答条件に含めない。
- Set切替は画像・モデル・判定対象を一緒に切り替える。マイク準備中／録音中は切替を無効化し、再生中の切替では再生を停止する。録音・認識・判定結果はセット／話者／行ごとに保持し、ページ内で戻った場合に復元する。ページ再読込を越える永続保存は追加しない。

## 4. Example 2・Drill 2 — なんですか

### 4.1 Example 2

- スマートフォンの例は次の3文で構成する。
  1. X：「私のスマホはこれです。」
  2. X：「Bさんのスマホはどれですか。」
  3. Y：「あれです。」
- 各文の音声操作は対応する1文だけを再生する。Xの2文は別行とし、同じキュー列・矢印・音声列の開始位置を共有する。Yの行には不要な空キュー欄を設けない。
- 「どれ」の疑問文で正答となる品物を先に強調しない。

### 4.2 Drill 2

- 「これは／それは／あれは、なんですか」と品名の返答を、2セット各3組で練習する。各組は質問X／返答Yの2行で、個別に再生・録音・判定する。
- Set 1はおにぎり・おべんとう・サンドイッチ、Set 2はトレーナー・ジーンズ・くつを使用する。
- 返答では、正しい品名だけの自然な短答を許容する。登録されている場合は、話者視点が正しい指示語付きの返答も許容する。誤った指示語・品名は許容しない。
- 品物の色を正答指定に使用せず、色名を発話・ヒントに含めない。Set切替・録音結果保持はDrill 1と同じ原則に従い、録音キーはDrill 2用に分離する。

## 5. Drill 3 — どれですか

- スマホ・辞書・財布の各セットで、同じ品物のred／blue／greenをX側・Y側・遠方に1つずつ配置する。色と色見本は対象を特定するキューとして使用し、色名を発話させない。
- 質問は「対象の所有者／品名／どれ」の構造とする。スマホ・辞書の対象では該当する設問で「あなた」を使用する。財布セットでは話者と所有者を明示し、問題1は「Yさん／さいふ／どれ」、問題2は「Xさん／さいふ／どれ」とする。
- 1セット2問とし、問題1はXが質問してYが返答、問題2はYが質問してXが返答する。

| セット | 対象色（問題1→2） | Formalの返答（問題1→2） |
| --- | --- | --- |
| スマホ | red → blue | それです。→それです。 |
| 辞書 | blue → green | これです。→あれです。 |
| 財布 | green → red | あれです。→これです。 |

- 返答では、返答者の視点に合う「これ／それ／あれ」を必須とする。色だけ・品名だけの回答や誤った指示語は正解としない。
- 財布セットでは質問者／所有者の対応を維持し、問題1はYさんの財布、問題2はXさんの財布を尋ねる。所有者を取り違えた補完文は正解としない。
- 「どれ」の質問時に正答となる品物を先に強調しない。返答で指示語を用いて対象を示す段階では、該当する品物を強調できる。
- Set切替は品物・画像・キュー・モデル・判定対象を同期させ、録音キーはDrill 3専用とする。設定変更・Set切替後も既存の録音・認識・判定結果を保持する。

## 6. English Cues（D4）

- English CuesはDrill 1〜3の問題キューだけを英語／日本語へ切り替える。Example、画像、画像内ヒント、モデル音声、期待文、許容回答、判定条件は変更しない。
- 切替前後で録音・認識・判定結果およびSet選択を保持し、English Cues用に独立した録音問題を複製しない。ページ再読込を越える永続保存は追加しない。
- マイク準備中／録音中は切替を無効化する。切替時は進行中のモデル再生を中断する。切替後のスクロール先・余白は `PROJECT_SPEC.md` §7.1の共通規則に従う。

## 7. 話者強調・対象品物の強調

### 7.1 話者強調

- Practice 2.1では、モデル音声再生、学習者の録音音声再生、マイク準備、録音中に、実際の話者に対応する画像内外の人物だけを強調する。
- 発話者が交代した場合は対象を切り替える。再生・録音の終了、中断、エラー時には強調を解除する。フォーカス移動だけでは発話中の強調を開始しない。
- 外観・アニメーション・reduced-motion時の扱いは `UI_LAYOUT_SPEC.md` §7.3を正本とする。旧方式の赤点滅を現行表示として適用しない。

### 7.2 対象品物の強調

対象品物の青枠は話者強調とは別機能とし、質問時に正答を先に示さない。Practice 2.1では、再生・マイク準備・録音中に次の対象を強調し、対応する処理の終了・停止時に解除する。

- Drill 1（Set 1／Set 2）：各行の指示対象品物。
- Drill 2（Set 1／Set 2）：各行の指示対象品物。
- Example 2：導入文および返答文に対応する品物。どれを尋ねる質問文では強調しない。
- Drill 3：返答行に対応する品物。どれを尋ねる質問文では強調しない。

## 8. 設問別の回答許容と判定

- 回答許容は設問ごとに登録し、ある設問の短答・助詞省略・指示語の例外を、他の行やPracticeへ自動拡張しない。
- Drill 1 Set 2の返答は「いいえ、ノートです」等の短い訂正を基本とし、「いいえ、それはノートです」「いいえ、鉛筆じゃないです。ノートです」等の正しい全文補完も許容する。「いいえ」の省略は許容できるが、誤った指示語・訂正語、否定だけで訂正がない回答、無関係な余分の文は正解としない。
- Drill 2は、設問に対応する正しい品名の短答を許容する。指示語を補う場合は話者視点・品名とも正しくなければならない。
- Drill 3は指示語が回答の中心であるため必須とする。「それは私のスマホです」「私のスマホはそれです」「スマホはそれです」「それは私のです」等は、該当する設問の話者・所有者・品物・指示対象が一致する場合に限って許容する。品名だけの回答、誤った所有者・対象・指示語は正解としない。
- 録音時点の文体・許容回答・判定結果を保持し、後からSpeech Styleを変更したことだけを理由に保存済み結果を再判定しない。共通のraw STT、表示用STT、判定用正規化の分離は `PROJECT_SPEC.md` に従う。

## 9. 回答判定・Feedbackの保持（Practice 2.1〜2.3共通）

本節はPractice 2.1〜2.3に共通する回答判定状態の保存・復元とMismatch表示配置を定める。Feedbackアイコン自体の外観・色・サイズは `UI_LAYOUT_SPEC.md` §9を正本とする。

### 9.1 判定ステータス

- 既存の許容解答・正規化・照合式と `isCorrect` を保持する。
- 新規保存では、`isCorrect: true`の場合に`judgment: 'accepted'`、`false`の場合に`judgment: 'mismatch'`を付加する。判定状態はAccepted／Mismatchの2種類とし、第3の状態を生成しない。
- 短い回答、部分一致、未知語、許容解答との不一致、複雑な日本語、推測した信頼度を理由にMismatchを別状態へ再分類しない。

### 9.2 保存・復元・エラー

- 旧データは既存の真偽値から表示状態を復元し、再採点や上書きを行わない。
- 録音URLの保持と判定結果の保持は独立して扱う。
- 再回答、Set切替、Script Mode切替、English Cues切替、再描画を行っても、保存済みの判定結果・ステータスを復元する。
- 未回答状態や録音開始処理では新しい判定を生成しない。
- 無音、結果なし、マイク失敗、SpeechRecognitionエラー、キャンセル、Audio onlyは、各ページの既存の録音・エラー処理に従う。

### 9.3 Mismatch Feedbackの配置

- Mismatchでは **Microsoft Fluent Fire Regular（20×20px）→ 認識テキスト → `Keep going!`** の順に表示する。
- Fireと認識テキストの間隔は4px、認識テキストと`Keep going!`の間隔は6px。認識テキストの赤字差分、不足マーク、raw STT由来の文字列を保持する。`Keep going!`は途中で分割しない。
- 結果全体は右寄せを基本とし、操作ボタン・停止ボタン右の疑問文マーク等が実際に占有する幅を確保した残余領域で、認識テキストを可能な限り1行目から表示する。認識テキスト全文の長さだけを理由に結果全体を次行へ送らない。
- 結果欄は縮小可能な可変幅とし、長い日本語や空白のない英字も自然に折り返す。各行は右寄せとし、Fireアイコンだけが孤立しないようにする。
- Fireと認識テキスト先頭2文字相当の最小幅が、実測した残余幅に収まらない場合に限り、結果を右寄せの独立行へ移す。固定画面幅を切替条件にしない。
- `Keep going!`が結果列より広い場合も、Fireと認識テキストは可能なら操作列の横で開始し、文言だけを後続行へ送り、結果全体の右端に揃える。操作要素と重ねない。
- 操作ボタンが複数段に折り返す場合、操作列全体の外枠幅だけで残余幅を判断しない。ページ幅に制約した後、停止ボタンと同じ段にある操作要素の実幅を基準にする。必要な幅がなければ結果を独立行へ移す。
- Feedback表示規則によって録音、停止、再生、判定、保存の機能動作を変更しない。
