## 2. Practice 1.1 — Noun sentences

### 2.1 基本文型

- 基本文型は `N1はN2です` とする。
- 肯定・否定の両方を扱う。
- Formal／Informalでは、通常のモデル・回答で主題を示す「は」を保持する。
- Casualでは、文脈上主題が明らかな場合に「は」を省略した回答を許容する。省略可能な助詞は「は」であり、「が」等へ一般化しない。

### 2.2 否定形とSpeech Style

否定形の許容は文体に応じて次のとおりとする。

| Speech Style | 許容する否定形 |
| --- | --- |
| Formal | じゃないです／ではないです／じゃありません／ではありません |
| Informal | じゃない／ではない／じゃないです／ではないです／じゃありません／ではありません |
| Casual | じゃない／ではない／じゃないです／ではないです／じゃありません／ではありません。ただしモデルの語尾は当該ページのCasualモデルに従う |

- 否定形6種類を、現行コードの一部が未対応であることを理由に仕様から削除しない。
- Formalでは丁寧形4種類を許容し、Informal／Casualでは6種類を許容する。
- モデル文の選択、表示、TTS、回答判定はそれぞれの役割を分離する。回答形の許容はモデル文の文字列と完全一致することだけを条件にしない。

### 2.3 主題「は」の省略

- Casualでは、主題を示す「は」を省略した回答を許容する。
- Formal／Informalへこの省略を自動拡張しない。
- 「は」の省略を認めることは、「が」等の別の助詞への置換を認めることではない。

**現行実装の確認済み事項**

- `practice1.1.js`後半のSpeech Style別判定処理は外側の`speechStyle`を参照する。
- `matchesSentence()`はCasualの場合に、回答候補から「は」を除いた形との照合を行う。
- `matchesFreeSentence()`にもCasual用の別経路があり、登録済み／既知の主語を用いて「は」の省略を扱う。
- `tests/practice11-topic.cjs`には`私学生だよ`をCasualで許容するアサーションがある。

このため、Casualの「は」省略は仕様・実装ともに解決済みとして扱い、未解決の問題や実装修正対象として再掲しない。テストファイルのアサーションを確認したことと、今回テストを実行したことは区別する。テストを実行していない場合、実行済みとは記載しない。

### 2.4 Drill 3 — Free input

- With Kanjiでは、学習者の入力が登録された名詞文の基本文型・文体条件を満たすかを判定し、X／Yの文字列完全一致だけで不正解にしない。
- Hiragana Onlyでは、任意の自由入力文に対して漢字変換・文字列抽出を前提とする判定を行わない。対象Drillは音声練習として扱い、録音音声の保持・再生を損なわない。
- 文型判定の許容範囲をPractice 1.2や他ページへ自動的に転用しない。

## 3. Practice 1.2 — Yes/No and Wh questions

### 3.1 回答の基本原則

- 各設問に登録された短答または全文回答の形式に従う。すべての設問に短答・全文の両方を一律要求しない。
- 回答に人物・所有者・対象が含まれる場合は、設問で指定された人物・対象と一致させる。
- Yes/Noでは選択した肯定／否定と回答文の極性を一致させる。肯定選択と否定文など、矛盾する回答は許容しない。
- Casualでは、ページ内で定めた既存範囲に限り、文脈から明らかな主語・目的語を省略できる。
- `うん／ううん`等の短い応答は、設問と選択状態に応じて登録された範囲で許容する。すべての回答に無条件で適用しない。

### 3.2 Drill 2 — 専攻

- `の専攻`を含む設問では、選択された専攻と回答内容の対応を確認する。
- 専攻の読み方・ポーズ等のTTS補助は、表示・raw STT・判定用文字列と分離する。
- Casualでの表示上の`ううん`とTTS内部の発音補助は別データとして扱う。TTS用補助を画面表示やraw STTへ書き戻さない。
- 回答形式の追加・許容は、該当する登録設問に限定する。`専攻`の例外を他の設問へ一般化しない。

### 3.3 Formal question

Formalの疑問文は、ページ仕様に登録された例外がない限り、終助詞「か」を必要とする。これは`PROJECT_SPEC.md`の共通回答判定に従う。

## 4. データ保持・判定上の共通制約

- raw STT、表示用STT、判定用正規化テキストを分離する。
- 回答判定で許容する表記揺れ・文体変化は、設問に登録された範囲に限る。
- 誤りを含む学習者の認識原文を、表示またはコピーのために自動修正しない。
- 録音結果・音声URL・回答選択・Script Mode／Speech Style等の状態は、既存仕様の範囲で保持する。
