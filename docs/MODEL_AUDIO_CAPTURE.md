# モデル音声の収録手順

## 起動

公開デプロイ後にChromeで以下を開く。

https://october2026.vercel.app/tools/model-recorder.html

ローカルではリポジトリ直下で `python3 -m http.server 8000` を実行し、`http://localhost:8000/tools/model-recorder.html` を開く。外部ソフト・拡張・npmビルドは不要。マイクの許可も不要。

## 最初の1項目（まずここまで確認）

1. 実際のVoice名を確認する。日本語3があれば初期選択する。不在なら自動で別Voiceを選ばない。WindowsではChromeOSと音声一覧が異なる場合がある。元の評価した声と違う場合は、本番収録前に採用する声を確認する。
2. 初期rateは発音ページと同じ0.9、pitchは1。試験用一覧の先頭は「箸。橋。」。初期一覧は正式なモデル一覧ではない。単独発話に変えるとアクセントも変わり得るため、まず現行の対語単位で確認する。
3. 他の再生・通知音を止め、「このタブの音声」→「共有を開始」。Chromeのダイアログでこのツールのタブを選び、音声共有を有効にする。
4. 「先頭1項目を収録」。収録後に波形・信号値が出る。下の保存音声を試聴し、対象Voice、意図したアクセント、語頭と語尾の欠けがないことを確認する。
5. 無音なら「共有を終了」。Windowsで「画面全体のシステム音声」に変更して再共有し、共有ダイアログで画面全体と音声共有を選んで再試験する。選べる共有範囲や音声チェックの名称はChrome／OSに依存する。
6. 音声トラックがあっても対象TTSが入るとは限らない。システム音声にも入らなければ、その環境では本方式の成功を確認できていない。一括収録に進まず、状況を報告する。

## 一括収録と保存

- 一覧は1行につき「ID＋タブ＋読み上げ文」。IDは英数字・ハイフン・下線の1〜80文字。重複不可、1〜500項目、文は500文字以内。初期の試験用2件は正式な全モデル一覧に置き換える。
- まず先頭1項目を収録・試聴し、確認欄にチェックすると「全項目を順番に収録」が使える。条件を変えたら試験・確認をやり直す。
- 収録中はVoice・速度・一覧・保存音声再生を禁止する。通知音や他アプリの音声はツールでは止められないため、収録前に止める。
- 「収録を中止」、共有停止、エラー・無音・期限切れでは後続を止め、完成済みの音声を保持する。同じIDの再成功で音声を置き換える。別Voiceのセットを作る場合は先にZIP保存する。
- 「収録済みをZIP保存」で1回のダウンロード。展開して各音声とmanifestを確認する。保存は自動永続化されず、再読込で消える。
- ZIP内容は `ID.webm` 等の収録原本、`ID.wav`、`manifest.json`。WAVは収録原本からデコードしたPCMであり、圧縮前の情報を復元したものではない。MP3変換なし。
- 無音試験のファイルも診断用に保存できる。manifestの `signalDetected` を参照し、音声の採用は必ず試聴で決める。

## 次工程

実機で収録経路が成功した後に正式な読み上げ一覧・Voiceを確定し、本番収録する。再生に採用する同じファイルからモデル曲線を生成する。固定音声とVoice切替の対応、Labへの搭載は別途実装する。今回、既存の練習ページは変更していない。
