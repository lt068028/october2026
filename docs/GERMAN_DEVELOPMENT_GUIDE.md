# ドイツ語ドリル開発・参照ガイド（German Development Guide）

**版：2026-11-08策定**  
**対象：Deutsche Übung シリーズ（`uebung*.html`, `uebung*.js`, `tests/uebung*.cjs`）**

---

## 1. 目的と開発方針

本書は、今後 Deutsche Übung 1.2 以降のドイツ語ドリルを新規作成・改修する際、**日本語ドリル（`practice*.js` 等）の実装ファイルを毎回横断的に調査する必要を排除し、開発効率を最大化するための作業標準ガイド**です。

現在の **`Deutsche Übung 1.1`（`uebung1.1.html` / `uebung1.1.js`）をドイツ語ドリルの第一参照実装**とし、仕様・構造・制御はこの実装と [ドイツ語ドリル専用仕様書](GERMAN_DRILL_SPEC.md) に基づいて行います。

---

## 2. Codexの参照優先順位

ドイツ語ドリルに関する作業を行う際は、必ず以下の優先順位でファイル・ドキュメントを参照してください。

| 順位 | 参照対象 | 目的・用途 |
| :---: | :--- | :--- |
| **1** | **対象のドイツ語ページ** (`uebung*.html`, `uebung*.js`) | 変更対象そのもののコード、DOM構造、現在のデータ |
| **2** | **ドイツ語専用仕様書** (`docs/GERMAN_DRILL_SPEC.md`) | ドイツ語ドリルの標準仕様、UI契約、音声制御、判定規則 |
| **3** | **ドイツ語専用テスト** (`tests/uebung*.cjs`) | 対象ページの契約検証コード、テスト期待値 |
| **4** | **必要な共通モジュール** (`drill-audio-session.js`, `style.css`, `tooltip-layout.js`) | 実際にドイツ語ページが直接利用している共通資産 |
| **5** | **関連する共通仕様書** (`docs/UI_LAYOUT_SPEC.md`, `docs/PROJECT_SPEC.md`, `docs/RELAY_WORKFLOW.md`) | サイト全体の幅配分契約、リレー手順、仕様書管理方針 |

## 3. 日本語ドリルファイルの参照禁止と例外規定

### 3.1 原則禁止
通常のドイツ語ドリルの新規作成、修正、リファクタリング、不具合調査では、**日本語ドリル（`practice*.js`, `practice*.html`, `composition*.js`, `pronunciation*.js` 等）を横断検索・参照してはならない**。

### 3.2 例外条件（日本語ファイルの参照が許可される4ケース）
以下に該当する場合に限り、例外として日本語ドリルファイルを参照することができます。
1. **共通モジュール仕様の判断困難**: 共通モジュール（`drill-audio-session.js` 等）の細部仕様や利用制約が、ドイツ語側の資料やコードだけでは確定できない場合。
2. **日本語固有機能の新規移植**: 日本語側にしか存在しない新しい機能（例: 新たなUIコンポーネントや録音分析等）をドイツ語ドリルへ初めて移植・導入する場合。
3. **共通機能変更時の影響調査**: `drill-audio-session.js` や `style.css` の共通セレクタを変更する際、日本語側への波及を調査する必要がある場合。
4. **既存テスト失敗の原因分析**: 変更によって日本語ドリルの既存自動テスト（`tests/*.cjs`）が失敗し、日本語側の文脈分析が必要となった場合。

### 3.3 作業報告への明記義務
例外的に日本語ファイルを参照した場合は、作業報告において **「参照した日本語ファイル」および「参照が必要となった例外理由」を簡潔に明記** すること。

---

## 4. 共通モジュール変更時の回帰テスト方針

`drill-audio-session.js`, `style.css`, `tooltip-layout.js` などの共通モジュールを変更する場合：

1. **フォーク（複製）の禁止**:
   - 共通モジュールをドイツ語専用に複製（例: `drill-audio-session-german.js` 等）することは厳禁。常に単一の共通モジュールを共有する。
2. **既存自動テストによる影響確認の優先**:
   - 共通モジュールを変更した際の影響確認は、**既存の自動テストスイート（`tests/*.cjs`）の実行を最優先**する。
   - 全日本語ページのソースコード（数百行〜数千行）を無条件に読み込んで目視確認するような作業は行わない。
3. **変更の局所化**:
   - ドイツ語固有のスタイルは `style.css` 内の `.uebungXX-page` スコープ内に閉じ込め、共通セレクタの上書きを最小限に留める。

## 5. 調査効率化の具体的ルール

作業コンテキストの浪費を防ぎ、手戻りのない迅速な開発を行うため、以下のルールを遵守する。

- **直接依存の特定**: 作業開始時に、対象ページと直接依存するファイル（HTML, JS, 専用テスト）のみを特定する。
- **行範囲指定の活用**: ファイル全体を無差別に読み込まず、関係のある関数・行範囲だけを `read_file` の行指定で読む。
- **重複読み込みの防止**: 一度読み込んだファイル・関数を同一会話内で何度も読み直さない。
- **「参考になりそう」による探索の禁止**: 日本語ページを「何か参考になるかもしれない」という曖昧な動機で探索しない。仕様書（`GERMAN_DRILL_SPEC.md`）と第一参照実装（`uebung1.1.js`）を優先する。
- **段階的スコープ拡大**: 不具合の原因が特定できない場合に限り、対象コード → 共通モジュール → テスト → 共通仕様書の順に、必要な範囲を段階的に広げる。
- **安全確認の省略禁止**: 効率化を理由に、構文検証（`git diff --check`）、テスト実行、コミット・Push手順などの安全確認を省略してはならない。

## 6. 新規ドイツ語ドリル（Deutsche Übung 1.2+）作成の標準手順

1. **第一参照実装からの複製**:
   - `uebung1.1.html` をコピーして `uebung1.2.html` を作成（タイトル、見出し、スクリプトパスを更新）。
   - `uebung1.1.js` をコピーして `uebung1.2.js` を作成。
2. **カリキュラムデータ（`drillsData`）の差し替え**:
   - `drillsData` 配列内のタイトル、指示文、`example`、`items` を新しい学習目標に合わせて記述。
   - 必要に応じて `highlightGrammar()` のハイライト対象単語（前置詞・冠詞等）を調整。
   - 地域変種がある項目は `regionalModels` および `allowedAnswers` を定義。
3. **専用テストの作成と実行**:
   - `tests/uebung11.cjs` を基に `tests/uebung12.cjs` を作成し、タイトル・設問数・地域設定を適合。
   - テストを実行し、全項目合格を確認。
4. **ナビゲーション登録**:
   - `index.html` に新しいドリルへのリンクを追加。
5. **検証・コミット・Push**:
   - `git diff --check` を実施し、`main` ブランチへコミット＆Pushする。
