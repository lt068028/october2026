# 8.1 共通仕様の取り込み漏れ：原因と是正

確認：2026-10-30。対象コミットa4bc73e（初回実装）、6be63f3（前回改訂）。現行色を維持するユーザー指示に従い、新しい候補色は採用しない。

## ゴールド

- 既存のUI_LAYOUT_SPEC「区分と強調」には、通常#ca8a04、ダーク#fbbf24が明記されていた。style.cssのgrammar-highlightにも実装されていた。仕様がなかった事案ではない。
- a4bc73eで新規のp81-goldクラスを作り、通常#906500・ダーク#ffd54fをページ固有CSSへ直接指定した。共通grammar-highlightを使わなかったため、共通仕様から独立した値になった。これらの値の採用を正当化するユーザー承認・仕様変更記録はない。
- 初回テストはゴールド要素の個数を確認したが、計算済みの色を共通仕様と照合しなかった。通常/ダーク画像の確認も、色値の仕様照合の代わりにはならなかった。
- 6be63f3で値自体は共通値へ戻し、色の計算値を検証するようにした。ただしページ固有CSSに同じ値を複製したままだった。
- 今回は文法強調に共通grammar-highlightクラスを直接使用し、ページ固有のゴールド色指定を削除。色自体は変えない。通常/ダークの計算値と、共通クラスの使用をテストする。

原因は実装時の共通仕様取り込み漏れと検証項目の不足。ブラウザや利用者側の色設定の問題として扱わない。数値を選んだ追加の設計根拠はコミット・仕様に残っていないため、推測で補わない。

## Yes/No Example

- 1.2 Example1、7.1/7.2/7.3の該当Exampleは、質問・肯定・否定モデルを示し、肯定🔊🙆/否定🔊🙅を独立再生する。
- UI_LAYOUT_SPECには既にExample再生とDrill選択の分離、練習7の質問/Yes/No縦列が規定されていた。一方、「新設する全Y/N導入Exampleで両返答を常時示す」という適用範囲は明確にまとまっていなかった。
- 8.1の前回改訂でD2のY/N選択・否定回答モデルは実装したが、Example2の配列には質問と肯定の2つだけを登録した。DrillのNo生成テストはあっても、Exampleの否定表示と専用ボタンを確認していなかった。
- 今回、UI_LAYOUT_SPECへYes/No Exampleの共通仕様を明文化し、8.1に3モデル・役割見出し・3音声の縦列・独立再生・返答語と語尾の共通強調を反映。Drillの選択・保存とは分離する。
- common-yn-examples.cjsで既存4ページ＋8.1を照合し、全文体で肯定/否定の常時表示、再生文の肯定否定、再生でDrill選択が変わらないことを検証する。

## Example音声の縦位置（2026-10-30追加確認）

- 親Gridはalign-items:baselineだが、8.1でボタンへalign-self:startを指定したため、そのボタンだけがベースライン共有から外れていた。余白・ブラウザの不具合ではなく、実装した配置指定が原因。
- 1440px幅・Chromiumの先頭質問/モデル行で、1.2と7.3はボタン文字と本文の基線差0px、8.1は4pxだった。8.1の指定削除後は同条件で0px。値はこの測定環境の値であり、全OSの固定差とはしない。
- これまでのテストは音声列の左右位置を測っていたが、文字の縦方向の基線を測っていなかった。今回は広幅・通常/ダークのExample全行に基線差の検証を追加。外枠上端やボタン中心だけの比較にしない。
- 共通仕様への追従を宣言するだけでは防止できない。共通スタイルを利用し、競合する個別指定を避け、実際の計算値・配置と初期表示をテストする方針を提案。CIの必須化や共通Example生成部品への整理は今回未実施。
