# 録音後リレー再生の間隔点検（2026-10-29）

## 現行仕様

通常Drillの「モデル音声→自分の録音音声」にプログラム上の待機時間を入れない（0秒）。TTSの終了通知を受けた同じコールバック内でAudio.playを呼ぶ。再生監視期限・録音停止待ちのタイマーは、この間隔の設定ではない。

| --- | --- | --- |
| 1.1 | 0秒 | 同一終了コールバック内にAudio.play |
| 1.2 | 0秒 | 同上 |

| 7.2 | 0秒 | 同上 |
| 7.3 | 0秒 | 同上 |

| composition1 | 0秒 | 同上 |

全ページはdrill-audio-session.jsのplayRelayを使用。発音Labやモデルのない自由録音は、録音だけを再生する既存仕様なので2音声間隔の対象外。

検証：node tests/relay-zero-gap.cjs。疑似TTS/録音APIで、実際の録音完了経路からリレーを開始し、TTS終了コールバックから戻る前にAudio.playが呼ばれることを全12ページで検証（8.1追加：2026-10-30）。実音声を試聴した検証ではない。

## 聞こえる無音と区別すること

録音ファイルの発話前の無音、TTSの音が終わってから終了通知までの時間、ブラウザ/音声デバイスの再生開始時間は、待機設定0秒でも存在し得る。末尾の自動停止までの無音2秒は主として自分の録音の後ろに残るもので、リレーのモデルと録音の間に2秒を挟む設定ではない。今回、録音の先頭/末尾のトリミングや音声エンジン変更はしていない。

## 2.1「何ですか」の読み・抽出・判定

1. 従来はモデルのなん/なにをTTS専用で何へ変換し、読みをエンジン任せにしていた。何ですかの文脈は「なんですか」を明示して渡すよう修正。なに？だけのCasual等の表現は変更しない。
2. Hiragana表示は何を一律なにへ変換していたため、認識結果が「何ですか」であっても画面は「なにですか」になっていた。何ですかだけは文脈に合わせなんですかと表示する。
3. ユーザー確定：なんですか/なにですかは両方許容。正誤判定は継続し、生の認識文字列は保存する。表示の読み変換で元の発話や認識結果を書き換えたとは扱わない。これだけでTTSの発音品質や学習者の発音を断定しない。
